# 复刻过程故障排查记录

## `9` 键无响应

首次烧录完成后，`9` 键按下没有响应。排查轴体和热插拔接触后，检查到对应二极管焊点虚焊。对焊点补锡后，`9` 键恢复工作。

如果复刻时遇到类似现象，应先断开 Type-C，再检查轴体两根金属针是否插入轴座、轴座焊点、对应二极管方向及焊点。不要因为单键无响应就直接重烧整板固件。

## `Num` 键单按不稳定

### 现象与定位

`Num` 单按有时不产生预期响应，快速连按时更容易触发；按住 `Num` 再按其他键可以控制 RGB 灯效。排查中曾更换对应二极管、凯华轴座和轴体，现象仍在。

原项目的 [Vial 键位源码](../firmware/qmk/w17/keymaps/vial/keymap.c) 将左上角定义为 `LT(1,KC_NUM)`：短按发送 Num Lock，按住进入第 1 层。QMK 要等按键释放并判断按压时长，才决定是否发送短按键值。这个设计解释了本次观察到的单按与连按差异；它不等同于普通 Num Lock 键。

### 本次处理

2026-09-22，通过 Vial 协议把设备的第 0 层、矩阵 `(0,0)` 从 `0x4153`（`LT(1, Num Lock)`）改为 `0x0053`（普通 `KC_NUMLOCK`），随后读回 `0x0053` 验证写入。当时未修改源码、重新编译或烧录固件。

2026-09-30 再次读取设备，Num 仍为 `0x0053`，并备份了实际 4 层键位。仓库的 `default`、`via`、`vial` 三份 `keymap.c` 同步改为 `KC_NUM`，使后续新构建的默认值与实物一致。原作者 `w17_pad.bin` 和 `v1.0.0` 标签仍保留原来的双功能 Num 配置。

修改后左上角只负责 Num Lock，长按该键不再进入 RGB 控制层。若重新烧录、清空动态键位或恢复出厂配置后出现旧行为，可按[键位说明](keymap.md)在 Vial 中再次设置。

## 排查顺序

1. 单键无响应：交换轴体测试，检查轴座、二极管和焊点。
2. 多键或 USB 异常：检查供电、Type-C 数据线、USB D+/D− 和驱动。
3. 按键“有时不响应”：确认 Num Lock 状态以及 QMK/Vial 是否定义了短按、长按或层切换。
4. 每次只改变一项，记录修改前后的表现；接触式 SWD 烧录时尤其要保持探针稳定。
